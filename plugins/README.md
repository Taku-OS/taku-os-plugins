# Plugin format / 插件格式

You usually don't need this page — the Agent's `taku-plugin pack` produces the right format for you. It's here for reviewers and anyone building by hand.

一般用不到这页——Agent 的 `taku-plugin pack` 会自动生成正确格式。这里写给审核者和手动制作的人。

## What a submission contains / 一次提交包含什么

Each version is exactly two files, both generated by `taku-plugin pack`:
每个版本只有两个文件，都由 `taku-plugin pack` 生成：

```
packages/<name>-<version>.zip      # the plugin itself / 插件本体
index/<name>/<version>.json        # its record and SHA-256 / 索引记录和哈希
```

Inside the ZIP is a single `<name>/` folder containing `.codex-plugin/plugin.json` (the manifest) plus whatever it declares. This `plugins/` folder only holds documentation — don't upload source here.
ZIP 里只有一个 `<name>/` 目录，含清单 `.codex-plugin/plugin.json` 和它声明的内容。本目录只放文档，不要往这里传源码。

## The manifest / 清单

```json
{
  "name": "status-tip",
  "version": "1.0.0",
  "description": "Shows a short reminder",
  "skills": "./skills/",
  "taku": {
    "capabilities": ["show a reminder"],
    "permissions": []
  }
}
```

| Field 字段 | Rule 规则 |
| --- | --- |
| `name` | Lowercase letters, digits, hyphens; 1–64 chars, starts with a letter or digit. 小写字母、数字、连字符，1–64 位，字母或数字开头。 |
| `version` | `major.minor.patch` (optional suffix allowed by the creator). 三段式版本号。 |
| `description` | Not empty. 不能为空。 |
| `skills` | Relative path to a folder with at least one subfolder containing `SKILL.md`. 指向插件内的目录，至少一个子目录含 `SKILL.md`。 |
| `mcpServers` | Relative path to a JSON file with an `mcpServers` object. 指向含 `mcpServers` 对象的 JSON 文件。 |
| `taku.capabilities` | What it can do — list of non-empty strings. 能做什么。 |
| `taku.permissions` | What it needs — list of non-empty strings; empty if none. 要用什么权限，没有就留空数组。 |

At least one of `skills` or `mcpServers` is required, and both must stay inside the plugin folder. Extra native fields such as `author` and `interface` are kept as-is.
`skills` 和 `mcpServers` 至少有一个，路径都不能跑出插件目录。`author`、`interface` 等原生字段会原样保留。

The [JSON Schema](manifest.schema.json) checks the manifest's shape; CI additionally checks paths and that the ZIP matches its index record.
[JSON Schema](manifest.schema.json) 检查清单结构；CI 另外检查路径，以及 ZIP 与 index 是否一致。
